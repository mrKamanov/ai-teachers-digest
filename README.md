# Factum Bot — как сделать бота для MAX, который пишет посты с помощью нейросети на GitHub Actions

Пример рабочего проекта: бот ежедневно **выбирает тему, пишет пост нейросетью, находит и проверяет фото и публикует всё в канал MAX** — полностью автоматически, без своего сервера. Всё происходит на бесплатных GitHub Actions, переписка с нейросетью и мессенджером — через их API.

Так работает канал [max.ru/channel_factum](https://max.ru/channel_factum) — эта репозитория является его рабочей движущей силой и одновременно инструкцией по её повторению.

## Как это работает

```
GitHub Actions (cron, 14:00 МСК)
        │
        ▼
scripts/daily_post.py
        │
        ├─ 1. Gemini выбирает новое место ──► история постов (history.json) даётся в промпт,
        │      (вместе с англ.запросами)      чтобы темы не повторялись
        ├─ 2. Gemini пишет пост              ──► стиль и эталон из prompts/
        ├─ 3. Викисклад (Commons API)        ──► ищет фото по англ.запросам из шага 1
        ├─ 4. Gemini-модератор смотрит фото ──► «узнаваемо ли место? нет запрещённого?»
        ├─ 5. MAX Bot API                    ──► загружает фото и публикует пост
        └─ 6. git commit                     ──► пост и история коммитятся (активность в репо)
```

Структура:

| Файл | Назначение |
|---|---|
| `.github/workflows/daily-post.yml` | cron-расписание, секреты, сборка TLS-бандла, коммит |
| `scripts/daily_post.py` | весь пайплайн: выбор темы → текст → фото → публикация |
| `scripts/get_chat_id.py` | разовая утилита: узнать `chat_id` канала |
| `prompts/story.txt` | промпт генерации поста (плейсхолдеры `{place}`, `{history}`...) |
| `prompts/style_example.txt` | эталон стиля — пост, написанный автором канала вручную |
| `history.json` | журнал опубликованных мест: защита от повторов + защита от двойной публикации |
| `posts/YYYY-MM-DD.md` | архив сгенерированных постов |
| `config/places.json` | запасной список мест (если Gemini недоступен) |
| `certs/*.pem` | корневые сертификаты НУЦ Минцифры (см. «Грабли») |

## Инструкция: сделать так же

### 1. Бот в MAX

1. Зарегистрируйтесь в [MAX для бизнеса](https://max.ru/business_bot?startapp) или через [business.max.ru](https://business.max.ru/self) → «Чат-боты» → создайте бота.
2. Заберите токен: ⋮ → **Настройки** → значок копирования справа от поля с токеном.
3. Бот уходит на модерацию (до ~24 часов).
4. После модерации добавьте бота в свой канал и назначьте **админом с правом писать**.
5. Узнайте `chat_id` канала — API не даёт список каналов бота, ID приходит только событием `bot_added`:
   ```bash
   export MAX_BOT_TOKEN=...   # токен бота
   python scripts/get_chat_id.py   # запустить ДО добавления бота в канал
   ```
   Скрипт напечатает `CHAT_ID: -123456...` (число со знаком минус). Подойдёт и ID из адресной строки веб-клиента: `web.max.ru/-123456...`.

Ключевые моменты API (документация: [dev.max.ru/docs-api](https://dev.max.ru/docs-api)):
- Базовый URL — **`https://platform-api2.max.ru`** (старый `platform-api` считается устаревшим)
- Заголовок `Authorization: <токен>` (токен в query-параметрах больше не поддерживается)
- `POST /messages?chat_id=<id>` — тело `{"text": "...", "notify": true}`
- Картинка: `POST /uploads?type=image` → загрузить файл по выданной URL → в `POST /messages` передать `{"attachments": [{"type": "image", "payload": {"token": "..."}}]}`

### 2. Ключ нейросети

1. [Google AI Studio](https://aistudio.google.com/app/apikey) → создайте ключ.
2. Модель: `gemini-3.8-flash` (старые `gemini-2.0/1.5-flash` отключены и отдают 404).

### 3. Репозиторий и секреты

1. Создайте пустой репозиторий на GitHub и залейте в него файлы этого проекта.
2. Settings → Secrets and variables → **Actions** → добавьте:
   - `GEMINI_API_KEY` — ключ нейросети
   - `MAX_BOT_TOKEN` — токен бота MAX
   - `MAX_CHAT_ID` — ID канала (без него пост всё равно сгенерируется и закоммитится, просто не опубликуется)

### 4. Расписание

`.github/workflows/daily-post.yml`:

```yaml
on:
  schedule:
    - cron: "0 11 * * *"   # 11:00 UTC = 14:00 МСК
  workflow_dispatch:        # ручной запуск для тестов
```

Каждый прогон: сгенерировать → опубликовать → закоммитить. Крон работает ежедневно; более частые интервалы возможны, но учтите лимиты GitHub (workflow не длиннее 6 часов, cron — не чаще раза в 5 минут).

### 5. Свои промпты и стиль

- `prompts/style_example.txt` — вставьте образец того, как вы пишете сами. Нейросеть копирует структуру, длину абзацев, интонацию.
- `prompts/story.txt` — промпт с плейсхолдерами: `{place}`, `{hint}`, `{history}` (список прошлых тем — защита от повторов), `{style_example}`.
- `config/places.json` → `photo.width` — ширина искомого фото; `photo.enabled: false` — отключить фото вообще.
- Темы мест сегодня выбирает сама нейросеть (с учётом истории); статичный список в `config/places.json` — только запасной вариант.

## Грабли, через которые мы прошли (чтобы вы не проходили)

1. **TLS-сертификаты Минцифры.** Многие российские сервисы используют НУЦ Минцифры («Russian Trusted Root CA»), которого нет в доверенных списках Ubuntu. Python на раннере будет падать с `CERTIFICATE_VERIFY_FAILED`. Решение — шаг «Trust MAX TLS certificates» в воркфлоу: собираем файл `/tmp/ca-bundle.pem` = системные CA + `certs/*.pem` и выставляем `SSL_CERT_FILE`. Важно: PEM-файлы должны быть в LF и с переводом строки в конце, иначе при склейке сертификаты «слипаются» и цепочка не собирается.
2. **Лимиты нейросети.** Бесплатный ключ отдаёт 429/503 — нужны ретраи с паузами (в скрипте: 4 попытки, 25→60→120 секунд). Режим «поиска в Google» (grounding) у бесплатного ключа практически недоступен — поэтому фото ищем через бесплатный Commons API, а нейросеть даёт только поисковые запросы и проверяет картинку.
3. **Двойная публикация.** Любой повторный запуск заново отправлял пост. Решение: после успеха в `history.json` ставится `published_to_max: true`, скрипт при старте проверяет эту отметку.
4. **Длинный ответ обрезался.** Модели с «мышлением» съедают лимит токенов на внутренние рассуждения — пост обрывался на середине. Решение: `thinkingConfig: {thinkingBudget: 0}` + `maxOutputTokens: 16384` + проверка минимальной длины.
5. **Фото-модерация.** Нейросеть-модератор отвечает строгим JSON `{match, safe, reason}` и проверяет каждую картинку перед публикацией: именно ли это место, нет ли запрещённого контента, карт, схем и рендеров. Не прошло — проверяется следующий кандидат, максимум 5.
6. **Коммиты от бота не дают активности профилю.** В воркфлоу задайте свои `user.name`/`user.email` (noreply вида `ID+login@users.noreply.github.com`), и каждый пост будет зелёным квадратиком на вашем профиле.

## Секреты (Settings → Secrets → Actions)

| Секрет | Откуда |
|---|---|
| `GEMINI_API_KEY` | [aistudio.google.com/app/apikey](https://aistudio.google.com/app/apikey) |
| `MAX_BOT_TOKEN` | MAX для бизнеса → Чат-боты → ⋮ → Настройки |
| `MAX_CHAT_ID` | `python scripts/get_chat_id.py` или адресная строка веб-клиента MAX |
